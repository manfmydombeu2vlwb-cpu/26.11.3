# Google Ads 投放判断手册 · 离线版

这是可直接打开的静态网站成品，包含知识文章、全文搜索、投放诊断、周复盘和词语整理工具。个人实操分享，非 Google 官方文档。

## 使用

1. 下载并完整解压仓库，保持 `Google_Ads_Offline` 目录结构。
2. 用 Chrome 或 Edge 打开本目录的 `index.html`。
3. 无需安装 Node.js、npm 依赖或启动服务器；样式、交互代码和搜索索引均已内嵌。官方参考链接需要联网。

可选的本地 HTTP 预览：在本目录运行以下命令，然后访问终端所示服务地址。

```bash
python3 -m http.server 8080
```

## 文件与维护

- `index.html`：首页和投放诊断。
- `map/`、`search/`、`video/`、`compliance/`：专题与文章。
- `toolbox/`：指标、复盘、词语整理与实验工具。
- `practice/`：搜索词、客户质量和回传练习。
- `about/`、`404/`：关于与未找到页面。
- `使用说明.txt`：离线版简明说明。

本仓库当前没有原始 `content/`、`src/`、`public/`、`scripts/` 或 `package.json`，因此不能在此运行 `npm run build` 或 `npm run check`。直接修改 HTML 时，应同步所有页面的共用内嵌脚本，并验证搜索、移动菜单和本地记录功能。拿到完整源码后，应优先在源码中修改并重新生成离线版。

## 本地记录

记录保存在当前浏览器本地，不会上传到服务器。请定期使用 JSON 或 CSV 导出备份；更换浏览器、访问地址或移动离线文件后，旧记录可能无法直接读取。不要填写真实客户个人资料。

## 浏览器回归检查

仓库根目录的 `tests/browser-smoke.cjs` 覆盖搜索、诊断、搜索/视频复盘、词语工具、互动练习和阅读工具。它使用全新的浏览器上下文，不会读取个人浏览器记录。Playwright 仅供测试使用，网站运行不依赖它。

先启动上面的本地 HTTP 服务。若测试环境尚未提供 Playwright，可将测试依赖安装在仓库外：

```bash
npm install --prefix /tmp/google-ads-browser-check playwright
```

然后在仓库根目录运行（示例使用系统 Chromium）：

```bash
NODE_PATH=/tmp/google-ads-browser-check/node_modules CHROMIUM_PATH=/usr/bin/chromium node tests/browser-smoke.cjs
```

环境已提供 Playwright 时可直接使用已有模块路径。`CHROMIUM_PATH` 应指向实际安装的 Chromium/Chrome；未指定时优先使用 `/usr/bin/chromium`，否则使用 Playwright 已安装的浏览器。服务使用其他地址时，设置 `SITE_BASE_URL`。该检查通过 HTTP 运行，不代表已验证浏览器的 `file://` 存储兼容性。

# Google Ads 投放判断手册

可搜索的 Google Ads 实操知识库、每周复盘工具与投放决策手册。个人实操分享，非 Google 官方文档。

## 技术选择

零运行依赖的 Node.js 静态内容构建器 + 原生 ES modules + JSON。此环境下静态内容和浏览器本地工具不需要服务端，选用更轻量、无框架升级负担的实现。每篇文章输出独立 HTML，直接访问和刷新都可用；正文无需 JavaScript，交互工具需要 JavaScript。后续可将内容目录迁移至 Astro/Next.js，文章与 UI 未耦合。

要求 Node.js 20 或更高版本。Python 仅用于可选本地预览，不参与构建。

## 安装、运行与构建

没有第三方 npm 依赖，无需运行安装命令；如需标准 npm 初始化流程，可运行 `npm install`（不下载第三方包）。

```bash
npm run build
npm run check
python3 -m http.server 8080 --directory dist
```

打开 http://localhost:8080 。不要使用 file:// 打开，否则模块与索引读取可能被浏览器阻止。修改内容后重新执行 `npm run build`，刷新浏览器。

发布时将 dist 部署到任意静态托管服务，支持目录 index.html。404 页面同时输出 dist/404.html 与 /404/。Sites 的身份与部署配置在 .openai/hosting.json。交付副本重新部署到新 Site 时，不应沿用原 project_id。

## 新增知识文章

在 content 对应专题目录新增 UTF-8 JSON 文件。文件名与 slug 一致，slug 使用小写英文与连字符。Schema：

```json
{
  "slug": "new-topic",
  "title": "文章标题",
  "description": "说明读完能解决什么问题",
  "category": "search",
  "stage": "诊断质量",
  "keywords": ["关键词", "术语"],
  "updatedAt": "2026-11-02",
  "relatedArticles": ["form-cpa"],
  "content": {
    "when": "什么时候使用",
    "points": ["知识要点"],
    "case": ["明确标注为教学的案例"],
    "judgment": "个人判断",
    "decisions": [{"see":"看到什么","judge":"判断什么","next":"下一步"}],
    "pitfalls": ["常见误区"],
    "sources": [{"label":"官方参考","url":"https://support.google.com/google-ads/"}],
    "table": null,
    "diagram": false
  }
}
```

table 可设为 `{ "headers": ["列名"], "rows": [["单元格"]] }`。所有案例自动附带「教学示意 · 示例数据，非真实账户」。diagram 目前表示统一并行获客地图，不用于仿制后台。

构建自动发现文件，更新文章路由、专题卡片、侧栏与全文索引，无需修改导航组件。可在 build.mjs 的 order 数组调整现有文章阅读顺序；新文章默认会被发现，不要求手动注册。所有文章采用八段统一阅读模板。构建后运行 check 检查相关阅读与内链。

## 新增专题

在 site.config.json 的 categories 追加 id、name、description、color，并新建 content/<id>/。color 使用 blue / teal / orange 或扩展 CSS。专题页与侧栏自动生成。七项顶部导航是产品固定主入口，新增专题默认显示在侧栏；如确需新增顶栏入口，在 layout.mjs 的 nav 数组追加。内容分类不要使用 about、404 等已用保留路径。

## 相关阅读

relatedArticles 填目标文章的 slug，不填文件路径。可跨专题引用。删除或改名文章时同步所有引用，npm run check 会报告不存在的目标。上一篇/下一篇按构建顺序输出，相关阅读按作者显式指定顺序输出。

## 名称、颜色与布局

修改 site.config.json 的 name、shortName、description、updatedAt。主题色在 public/styles.css 的 :root：--blue、--teal、--ink、--orange。完整排版和交互规范见 docs/DESIGN.md。

## 搜索

构建时生成 search-index.json，包含标题、摘要、关键词与全部文章正文（知识要点、案例、判断、术语等）。浏览器按大小写不敏感的 NFKC 文本匹配；空格分隔的多个词采用 AND，标题与关键词优先排序。显示专题、摘要与命中词。支持 Ctrl/⌘ K、Esc、键盘 Tab 与原生 dialog 焦点约束。中文请使用短关键词；不依赖在线搜索服务，不做语义检索。索引只含文章公开教学内容，绝不包含周复盘记录。

## 周复盘数据

localStorage 键：ads-manual:review:v1:search 与 ads-manual:review:v1:video。字段包括复盘日期、系列、获客批次、成熟度、币种、花费、点击、表单、合格、成交、价值，以及搜索词/素材、改动日期、原因、下周验证指标等。

表单 CPA、合格 CPA、成交 CPA 与合格率由模型实时计算。分母为空或零显示“—”；0 与未填写分开处理。表单、合格、成交按去重客户口径；成交不得超过合格，合格不得超过表单。视频另有曝光、观看、频次、观看相关转化与口径说明。辅助转化单列，不与直接成交相加。

保存后编辑同 ID 记录；新建清空当前表单；删除/清空档案有二次确认。支持当前记录与历史记录打印，建议浏览器打印为 PDF 留档。JSON 导出只含已保存记录；导入同类备份按 ID 合并，已有记录不覆盖。教学示例携带 isExample 标识，保存、编辑、导入与打印均保留。存储不可用/损坏时阻止覆盖，显示错误并保留打印能力。

这些记录只在同浏览器、同 origin 下持久保存，没有服务器数据库、账户同步或 Google Ads API。清理浏览器数据会删除本地档案。迁移域名时先导出、再到新地址导入。请勿写入真实客户个人资料。多人或多设备协作需求应另行设计身份与服务端存储。

## 内容维护原则

搜索和视频始终是两条并行路径，各自追到线索、合格与成交。最终比较客户质量、成熟周期与价值，去重后再汇总。自动化前检查目标和回传。每次只验证一个核心变量。

所有示例非真实账户。页面不含模拟官方后台截图。术语与功能需在维护时查当前官方帮助，行业合规需另行按地区与业务核查；本站不提供政策通过保证。

## 检查与交付

npm run check 扫描全部输出的内部链接/锚点、统一文章结构、Schema、免责声明与占位文本，验证全文搜索、计算边界、存储读写、编辑、删除、数据隔离与备份。浏览器实测记录见 docs/VALIDATION.md；完整路由树见 docs/ROUTES.md。源项目与部署文件分开，dist 可随时从内容与组件重新生成。

搜索词报告页给出 2026-11-02 核对的官方入口、列设置、导出与分类步骤，并提示范围与隐私限制。关键词研究页区分 Keyword Planner 的候选词、Google Ads 实际查询、Trends 相对热度、Search Console 自然搜索。外链需联网、账户相关操作需对应权限；本站不自动访问真实账户。

关键词整理台路径 /toolbox/keyword-workbench/，localStorage 键 ads-manual:keywords:v1。支持词语来源、日期、实际查询与触发关键词、主题、意图、拟定动作、理由、否定范围与复查日期；增删改、搜索过滤、CSV 导出/导入、打印。只有已保存记录导出。CSV 使用 UTF-8 BOM，按本工具固定表头导回，以 ID 合并，同 ID 保留当前版本。导出中潜在公式内容前加单引号，防止表格软件当公式执行；导入恢复原始文字。关键词记录与复盘记录分开。

复盘工具新增字段来源解释、教学示例入口、跟进状态拆分、数据解释和前一期对照。选择同系列、同币种、已成熟且已完成跟进、日期更早的记录后才作为可比参考；教学示例不能与实际记录混比。比较仅作描述，批次长度、资格标准、季节与样本充分性仍由业务人工核对。保留 v1 存储键，已有复盘记录仍可读取，不删除或迁移用户档案。

离线成品可使用 `node scripts/build-offline.mjs /绝对输出目录` 生成。它内嵌样式、搜索索引与浏览器代码，将页面链接转为相对文件路径，生成后双击根目录 index.html。file:// 下的存储行为取决于浏览器，请导出备份，不要假设移动目录后数据仍在。离线构建不改变在线部署目录。原 create-content.py 属初版种子脚本，不要在 V2 内容上重新运行。

## V3：字体与信息密度

默认文章正文18px，阅读工具可切换更大字号；“更大字号”偏好仅保存在当前浏览器。首页精简为三个任务入口；侧栏按专题折叠，只展开当前专题。文章的补充部分按需展开，操作步骤默认展开第一步，可一键展开全部。来源与案例内容保留在原文章数据中，全文搜索仍覆盖所有内容。带章节锚点的链接会自动展开目标章节，打印时展开正文并在打印后恢复原状态。

字体与折叠样式在 public/styles.css 的 V3 段落。布局、文章结构和首页分别在 layout.mjs、article.mjs、guidance.mjs 中维护；未删改知识正文或已有本地复盘/关键词记录。

## V4：从阅读入口改为实操工作台

首页直接展示可交互的教学数据台，三个主题分别为搜索词筛选、客户质量与转化回传，另有独立路由 /practice/terms/、/practice/quality/、/practice/feedback/。所有练习均为教学示意，不连接、读取或修改 Google Ads 账户，不是官方后台仿制界面。

数据与组件仍分离：data/practice.json 管理业务范围、搜索词及反馈节点，src/components/practice.mjs 管理练习视图，public/practice-model.mjs 管理可独立验证的统计与成本计算，app.js 负责操作。新增数据要保持费用、表单、合格、成交口径一致；所有观点应标明教学假设。

搜索词练习：点选一个查询，选择保留、待核对排除或补信息，查看对应业务证据；可筛选待排除和未判断词，显示判断进度。排除清单只作历史示例回看，不把历史花费等同于未来节省。演示结果保存在页面内存，刷新重置，不写入真实关键词档案。

质量练习：调整花费、表单数和0–100%合格率，图示用100格表示比例，实时计算表单与合格CPA；0%时合格CPA为不可计算，示例理论人数可为小数，真实复盘仍需整数客户数。与原批次的对照只作教学解释，不提供预算或利润结论。

回传练习：点击网站提交、CRM合格、反馈客户结果、成交复盘节点，展示每步责任、输入、输出和容易漏掉的问题。这是线索数据流程，搜索/视频的获客关系仍为并行。

主要文章和专题页增加练习入口，文章列表按需展开。知识文章、复盘记录和关键词整理数据均保留；现有localStorage键不变。离线构建同时内嵌练习数据、模型与交互代码，无需fetch额外数据。官方外链仍需联网。

## V5 图解优先阅读

15 篇知识页默认展示「点选图解 → 当前节点的一句说明 → 深色判断条 → 动手入口」，完整原文位于「完整文字手册」折叠区。搜索仍覆盖完整内容；目录和锚点会展开对应说明；打印会展开全文并在打印后还原。

图解内容独立保存在 `data/visual-lessons.json`，按文章 slug 关联。每项包含 `title`、`subtitle`、`kind`、`takeaway`、`nodes`、`cta`。节点结构为 `[唯一ID, 短标签, 图标名, 说明, 可选入口URL]`。渲染器为 `src/components/visual-lesson.mjs`，交互在 `public/app.js`，视觉规则在 `public/styles.css`。新增文章不配图解时，会从文章步骤自动产生基础流程图，无需修改导航。

当前图形包括：两条并行获客路径、搜索意图分类、两批客户的 100 点对照、三层指标、视频分镜、检查清单、数据回传和实验过程。数值图必须与内容文件及教学数据一致，不能用装饰比例替代真实分母。渠道缩略图也保持搜索与视频并行。外链用于真实工具和官方资料，站内示意均有教学标识。

## 中英对照维护

`public/bilingual.mjs` 集中维护英文词和中文解释。构建时处理可见正文及提示，浏览器展示新生成的搜索结果、图解节点与工具说明时也会补充翻译；不会改写 URL、脚本数据、用户输入或保存的原始关键词。已有中文解释不会重复添加。英文搜索词有单独中文行时，可用 `data-no-translate` 保留英文原样。新增英文示例应同时补充中文，维护字典时优先核对行业术语含义。

## 广告数据判断工具（首页 / 工具箱）

首页现为数据判断台，独立入口 `/toolbox/diagnosis/`。全站 36 路由，21 篇手册继续用于解释判断依据；原实操练习保留在 `/practice/terms/`、`/practice/quality/` 和 `/practice/feedback/`。

### 使用

1. 选择搜索或视频，并填写同一获客批次的花费、点击、表单、已完成跟进、合格线索、成交等汇总数。空白为未知，0 为确认没有。视频还可选择观看或覆盖任务。
2. 可选填写业务可接受的客户成本与自定样本门槛；可添加上一批次进行对照。只有成熟、全部跟进、日期不重叠且用户确认口径一致时，才输出客户成本变化判断。
3. 点击生成，查看优先检查项、计算结果、证据与下一步。填写一次行动和复查日期后保存。支持查看/编辑、删除、打印，以及 JSON 备份导出/导入；导入相同 ID 保留本地版本。

### 结构与维护

- `src/components/diagnosis.mjs`：表单与页面外壳。
- `public/diagnosis-model.mjs`：纯函数验证、计算、规则优先级、记录读写与备份合并。
- `public/diagnosis-ui.mjs`：输入、结果呈现和本地历史。
- `scripts/check-diagnosis.mjs`：规则与存储边界测试，由 `npm run check` 自动运行。

规则版本为 1。保存记录包含原始汇总输入、判断快照、行动、复查日期与更新时间；再次打开记录会以当前规则重新计算，快照保留在备份中。更新判断逻辑时维护规则版本及历史兼容策略。

存储键 `ads-manual:diagnosis:v1` 独立于原搜索/视频周复盘与关键词记录。网页和离线版均在浏览器本地计算，不连接 Google Ads API，不上传输入。每个浏览器/站点地址或离线路径的记录可能不同；请定期备份。只填写汇总数据，不填写客户个人信息。

### 规则边界

| 输入现象 | 输出方向 |
| --- | --- |
| 没有花费或花费/展示范围矛盾 | 先核对投放与数据口径 |
| 搜索有展示却无点击 | 核对搜索意图、广告表达与定位 |
| 有花费但没有表单 | 验收提交、事件、页面和流量 |
| 有表单但客户数据未知 | 先补客户结果，不把空白视为零 |
| 跟进不完整或客户未成熟 | 等待证据，不给最终预算结论 |
| 全部跟进后仍无合格客户 | 核对资格标准与流量筛选 |
| 表单更便宜但合格成本更高 | 优先排查客户质量，不据低表单成本扩量 |
| 可计算客户成本超过自定目标 | 排查并验证一个主要变量 |
| 两项客户成本达标、成熟且满足自定样本门槛 | 可规划受控测试，仍需确认利润、承接与保护条件 |
| 视频观看/覆盖任务 | 单独描述注意层，不冒充客户效果 |

没有统一 CTR、CPC、CPV 及格线，没有固定预算增幅建议。汇总数据不足以证明根因、增量或利润。自定样本门槛不代表统计显著性。金额最多两位小数，人数为整数；分母为零或未知时显示暂不可计算。客户尚未跟进完成时，只显示已跟进样本合格率。

## 判断工具自检修订（规则 1.1，存储格式仍为 1）

已修复历史批次缺值错误沿用本批数值的问题；历史指标独立计算，未知保持未知。对照还会核对广告类型、任务、系列与币种，客户数未知或跟进未完成时不作预算比较。新增合格成本/成交成本上升规则：即使仍在自定目标内，也先核对恶化原因。未来日期仅作待核对，不输出预算测试判断。

覆盖任务现显示展示、去重覆盖、平均频次与 CPM；缺少覆盖人数时保持未知，不从展示数假造人数。观看/覆盖指标继续与客户判断分开。

多页面写入会读取最新本地记录，合并无冲突的增删改；同一条记录发生冲突时阻止覆盖，并可另存新记录。备份导入限制为 25 MB，重复标识、错误类型和无效日期会被拒绝。导入和写入共用记录校验。未保存行动切换历史记录前会提示，取消后保留草稿。

原有存储键与旧记录继续兼容。规则版本和存储格式分开维护；旧记录重新打开时用当前规则计算，原判断快照仍可在备份中保留。离线和网页都属于当前浏览器的本地工具，不具备跨设备同步或多人实时协作能力。

## 第二轮自检（规则 1.2，存储格式仍为 1）

导出备份前会重新读取当前浏览器的最新记录，避免旧页面漏掉其他页面刚保存的条目。历史列表支持刷新，并响应其他页面更新；编辑器保留打开记录时的独立基准，列表更新不会取消同一记录的冲突保护。

上批次的系列、类型、任务、币种和教学标记作为独立口径保留。导入后编辑和重算不再丢掉这些字段。改变本批口径会取消对照确认；如需改用新口径，可明确点击「改用当前口径，清空并重填上批数据」，旧数值与日期不会被悄悄重新标为另一种币种。教学记录与实际记录不能混比。

行动草稿在重新计算时保留；清空或换用新教学数据后不再串入上一条行动。刷新列表、导入和导出均保留当前填写；保存只提交本次条目的增改，删除只提交目标条目，其他页面的新记录继续保留。

## 第三轮自检（规则 1.3）

成熟、完整跟进的获客批次若填写的成交价值低于广告花费，会先要求核对价值完整性与商业承受能力，不再仅因客户成本目标达标输出预算测试提示。该检查不把 ROAS 当作利润，也不自动认定未填写的价值为零。

日期异常、无花费、花费与展示矛盾、搜索点击为零却有表单等数据口径问题，先于“等待成熟/积累样本”的提示。视频零观看及有展示但零覆盖会给出对应核对提示。金额精度按原始十进制表示校验，避免浮点容差接受多位小数；过小数值不会静默变为零。

`npm run check` 现包含 360 组有效数据组合，验证指标有限、零分母不显示零成本、未完成跟进不生成完整合格率，以及预算测试与阻止提示不会同时出现。公式说明已修复异常文本，规则与存储版本分别显示和维护。
